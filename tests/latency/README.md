## 0. 性能基准

### 0.1 纯 anyproxy 性能 (本地测试)

在本地同时运行 Gateway + Client，排除网络延迟影响，测量 anyproxy 本身的延迟开销：

| 测试类型 | 直连 | 本地代理 | **anyproxy 开销** |
|----------|------|---------|------------------|
| TCP 控制 (128B) | 300µs | 2.3ms | **~2ms** |
| UDP 音频 (400B) | 90µs | ~2ms | **~2ms** |
| UDP 视频 (1.4KB) | 100µs | ~2ms | **~2ms** |

**吞吐量测试 (本地)**:

| 目标速率 | 直连 | 本地代理 | 丢包率 | 数据完整性 |
|----------|------|---------|--------|-----------|
| 20 Mbps | 20.0 | 20.1 | 0% | ✅ 100% |
| 50 Mbps | 50.0 | 50.3 | 0.1% | ✅ 99.2% |
| 100 Mbps | 99.9 | 100.6 | 0.3% | ✅ 98.4% |
| 200 Mbps | 199.7 | **201.2** | **1.3%** | ⚠️ 98.1% |

> ✅ **结论**: anyproxy 本身延迟开销仅 **~2ms**，吞吐量可达 **200Mbps+**。

### 0.2 网络基准 (Physical RTT)

```bash
$ ping -c 20 47.107.181.88
rtt min/avg/max/mdev = 11.576/14.289/15.596/1.389 ms
```

| 指标 | 数值 | 说明 |
|------|------|------|
| **物理 RTT** | **14.3ms** | 本地 ↔ 阿里云往返延迟 |
| 单向延迟 | ~7ms | RTT / 2 |
| 丢包率 | 0% | 20 packets |

> ⚠️ **重要**: 远程代理延迟 = 物理 RTT (~14ms) + anyproxy 开销 (~2ms) = **~16ms 理论最小值**。实测 25-30ms 包含了网络波动。

### 数据流路径

```
Moonlight (手机/PC)
    │
    │ ① SOCKS5 请求
    ▼
Gateway (47.107.181.88:1080)
    │
    │ ② QUIC 隧道 (加密)
    ▼
Client (本地)
    │
    │ ③ 转发到目标
    ▼
Sunshine (127.0.0.1:47984/47989)
    │
    │ ④ 响应数据原路返回
    ▼
Moonlight
```

### 关键组件

| 组件 | 位置 | 角色 |
|------|------|------|
| **Gateway** | 阿里云 (47.107.181.88) | 公网入口，提供 SOCKS5/HTTP 代理 |
| **Client** | 本地内网 | 连接 Gateway，转发流量到本地服务 |
| **QUIC 隧道** | Gateway ↔ Client | 加密传输，支持 Datagram（低延迟 UDP）|

## 4. 测试结果

### 4.1 延迟测试

| 测试项 | 直连 (P50) | 代理 (P50) | 代理 (P95) | 成功率 |
|--------|-----------|------------|------------|--------|
| TCP 控制命令 | ~150µs | **78ms** | ~100ms | ✅ 100% |
| UDP 音频 (400B) | ~90µs | **25ms** | ~36ms | ✅ 100% |
| UDP 视频 (1.4KB) | ~95µs | **29ms** | ~41ms | ✅ 100% |

**延迟分析**：
- 物理 RTT：~14ms（本地 ↔ 阿里云往返）
- 代理额外开销：~11-15ms（协议处理 + QUIC 握手）
- **总延迟 25-30ms**：完全满足游戏串流需求（人类反应时间 ~150-200ms）

## 5. 结论与建议

### 5.1 适用场景

| 场景 | 支持度 | 说明 |
|------|--------|------|
| 720p@30fps 游戏串流 | ✅ 完美支持 | 延迟 30ms，0% 丢包 |
| 1080p@60fps 游戏串流 | ✅ 完美支持 | 延迟 31ms，0% 丢包 |
| 4K@60fps 游戏串流 | ⚠️ 可能有问题 | 50Mbps+ 时需要测试 |
| 高带宽传输 (100Mbps+) | ❌ 不建议 | 丢包率高 |

### 5.2 性能优化记录

本次测试前进行了以下优化：

1. **QUIC Datagram 支持**
   - 启用 QUIC Datagram (RFC 9221) 用于 UDP 数据
   - 低于 1.2KB 的 UDP 包走不可靠传输，减少延迟

2. **缓冲区优化**
   - QUIC/gRPC readChan: 100 → 100,000
   - QUIC datagramChan: 1,000 → 100,000
   - BufferedConn 替代 net.Pipe() 避免阻塞

3. **日志优化**
   - 移除高频 DEBUG 日志
   - UpdateConnectionBytes 改用读锁 + 原子操作

4. **流控优化**
   - QUIC 流控窗口: 1MB → 6MB (单流)
   - QUIC 连接窗口: 2MB → 15MB (全连接)

### 5.3 推荐配置

对于 Moonlight/Sunshine 游戏串流：

```yaml
# Moonlight 客户端设置
分辨率: 1080p
帧率: 60fps
比特率: 20-40 Mbps  # 推荐
```

```yaml
# AnyProxy Client 配置
replicas: 3  # 多副本提高可靠性
transport_type: quic  # 使用 QUIC 协议
```
