## 三、问题分析与修复

### 3.1 已修复问题 ✅

#### 问题 1: 极端延迟 (7+ 秒) → **已修复**
- **原因**: `BufferedConn` 的 UDP 写入使用阻塞模式，buffer 满时无限等待
- **修复**: 实现 **drop-oldest 策略** - UDP buffer 满时丢弃最旧的包
- **效果**: Max Latency 从 7391ms/7657ms 降至 **42ms/116ms** (减少 98%+)

#### 问题 2: 500 Mbps@60fps 帧间隔异常 → **已修复**
- **原因**: 与问题 1 相关的队列积压
- **修复**: 同上
- **效果**: Max Interval 从 194.31ms 降至 **22.86ms** (减少 88%)

#### 问题 3: 吞吐量略有提升
- **修复前**: ~83-85 Mbps
- **修复后**: **~92 Mbps** (提升 10%)
- **说明**: 吞吐量仍受 localhost 环境和测试框架限制，但已有明显改善

### 3.2 仍需关注 ⚠️

#### 高帧率场景 Late Rate
- **现象**: 120/240/360fps 场景下 Late Rate 仍在 1.2-1.5%
- **影响**: 高刷新率显示器上可能感知到微小卡顿
- **原因**: Go runtime 定时器精度限制 + 系统调度抖动
- **建议**: 对于竞技游戏场景，建议使用 60-120fps

### 3.3 表现良好 ✅

1. **低负载延迟**: Video/Audio 延迟开销 <1ms，满足游戏串流要求
2. **基础吞吐**: 20-80 Mbps 场景完全正常，丢包率极低
3. **60fps 帧丢失**: 0% 帧丢失，完美表现
4. **数据完整性**: 所有测试 Integrity = 100%
5. **高吞吐稳定性**: 丢包率 <0.7%，延迟可控

## 四、已实施的修复

### 4.1 核心修复: UDP drop-oldest 策略 ✅

修改 `pkg/common/connection/buffered_conn.go`:

```go
const (
    TCPBufferSize = 5000   // ~6MB, TCP 保持可靠性
    UDPBufferSize = 2000   // ~2.4MB, 限制最大延迟 ~200ms
)

func (c *BufferedConn) writeInternal(data []byte) (int, error) {
    if c.isUDP {
        // UDP: 非阻塞，buffer 满时丢弃最旧的包
        select {
        case c.outChan <- data:
            return len(data), nil
        default:
            // Buffer 满，丢弃旧包
            select {
            case <-c.outChan: // 丢弃最旧的包
            default:
            }
            // 重试发送
            select {
            case c.outChan <- data:
                return len(data), nil
            default:
                return len(data), nil // 静默丢弃 (UDP 语义)
            }
        }
    }
    // TCP: 阻塞等待 (可靠性)
    // ...
}
```

修改 `pkg/common/protocol/protocol.go`:

### 4.3 队列深度监控 ✅

在 `pkg/gateway/client_conn.go` 添加监控:
